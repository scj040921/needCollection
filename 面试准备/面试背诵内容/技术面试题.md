# 1. TCP与UDP的区别
- TCP（传输控制协议）是一种面向连接的、可靠的、基于字节流的传输层通信协议，在使用tcp进行通信时，发送方和接收方需要先建立连接（三次握手），在通信接收后断开连接（通过四次挥手）。tcp提供了可靠的、顺序的无差错的数据传输，通过确认、重传、流量控制和拥塞控制机制保证数据传输的可靠性。
- UDP（用户数据报协议）是OSI参考模型中无连接的传输层协议，提供简单、不可靠的信息传输服务。UDP不进行连接的简历和断开，发送方和接收方直接发送和接收数据报文。UDP没有流量控制和拥塞控制，因此适用于实时性要求高、但对可靠性要求较低的应用
- **总结**：TCP适用于需要可靠传输和数据完整性的场景，而UDP用于对速度要求高但是可以容忍有一定丢包现象的场景。

无符号16位整数的取值范围是0到65535，由于没有符号位，所以16位二进制位都用于表示数值
## 有符号16位整数

# 3. 简述三次握手和四次挥手，如果客户端断开出现故障怎么办
## 三次握手
**1. 客户端发送SYN包**：客户端发送一个带有SYN标志的报文，告诉服务器请求简历连接，并且带有一个初始序列号（ISN）
**2. 服务器回应SYN+ACK包**：服务器接收到客户端的SYN包后，响应一个SYN+ACK包，表示同意连接并返回自己的序列号。
**3. 客户端发送ACK包**：客户端收到服务端返回的ACK+SYN包后，发送ACK包确认连接建立，至此连接正式建立
## 四次挥手
**1. 客户端发送FIN包**：客户端发送一个带FIN标志的包请求关闭连接
**2. 服务器响应ACK包**：服务器收到客户端的FIN包后，回应ACK包，确认客户端的关闭请求，但此时连接尚未断开。
**3. 服务器发送FIN包**：服务器完成数据传输后，发送一个FIN包给客户端，表示准备关闭连接
**4. 客户端回应ACK包**：客户端收到服务器的FIN包后，发送ACK包确认，连接关闭，服务器收到此ACK包后，完全断开连接
## 故障处理
如果客户端突然断电或者关闭，服务器将等待一段时间来确保客户端完成连接关闭。如果客户端未能正常断开，服务器会在超时后清理连接。如果客户端没有收到ACK或FIN包，可能会进行超时重传，确保连接最终正常关闭。
# 4. 网络的7层模型是什么
**物数网传会表应**：物理、数据链路、网络、传输、会话、表示、应用
**详细说明**：
- 物理层：负责数据的物理传输
- 数据链路层：负责在物理层之间提供可靠的数据传输，进行错误的检测与修正
- 网络层：负责数据的路由选择和转发，使用IP地址
- 传输层：确保数据的可靠传输
- 会话层：管理应用程序之间的会话，确保数据的同步
- 表示层：负责数据的格式化，加密和解密
- 应用层：直接与用户交互，提供各种应用服务
# 5. 互斥锁的作用，为什么会出现死锁
## 互斥锁的作用
互斥锁时专门用于处理线程互斥的一种机制。用于保护临界资源，确保同一时刻只有一个线程能够访问该资源。互斥锁有两种状态：上锁状态和解锁状态。如果互斥锁处于上锁状态，其它线程会被阻塞，直到当前锁被解锁；如果锁处于解锁状态，则可以正常上锁，不会阻塞。
## 死锁的原因：
死锁指的是由于线程间资源请求的循环依赖，导致线程无法继续执行
## 死锁发生的四个必要条件
1. 互斥条件：至少有一个资源必须处于被独占的状态
2. 请求与保持：线程已经持有某些资源，同时等待其它资源
3. 不剥夺条件：以获得的资源不能被强制剥夺
4. 循环等待条件：形成资源请求的闭环，多个线程相互等待
## 死锁的解决方法
1. 避免死锁：通过确保线程按照相同的顺序请求资源，或者使用锁超时机制，避免形成死锁。
2. 死锁检测：通过周期性检测资源分配图，检查是否存在循环等待
3. 死锁恢复：如果死锁已经发生，可以通过终止线程或者回滚操作来释放资源，恢复系统运行。
# 6. I2C的通信过程
**I2C**是一种同步串行通信协议，常用于微控制器与各种外设之间的通信。I2C通信通常包括两个阶段：主设备向从设备写数据和主设备从从设备读数据。
## 主设备向从设备发送数据
1. 起始信号（START）：主设备发送一个起始信号，SDA由高电平拉低，SCL保持高电平，标志着通信的开始。
2. 设备地址：主设备发送从设备的地址，地址通常是7位或者10位，地址后跟随一个读/写位（0表示读，1表示写）
3. 响应：从设备收到地址后，回应一个ACK信号，表示准备好接收数据
4. 数据传输：主设备发送数据，每个字节的数据后，从设备需要发送ACK响应，表示数据接收成功
5. 停止信号：数据发送完毕，主设备发送停止信号，SDA线从低电平拉至高电平，结束通信
