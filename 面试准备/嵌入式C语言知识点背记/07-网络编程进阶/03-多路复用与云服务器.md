# 多路复用与云服务器

## 为什么需要多路复用

一个进程可同时监视监听 socket、多个客户端 socket、管道或串口 fd；内核阻塞到“至少一个 fd 就绪”，避免为每个连接轮询或盲目创建线程。

| 接口 | 特点 | 适合 |
| --- | --- | --- |
| `select` | fd 集合位图、每轮重建、存在 `FD_SETSIZE` 限制 | 教学、小连接数 |
| `poll` | 使用数组，无位图 fd 上限 | 中等规模 |
| `epoll`（Linux） | 内核维护关注集合，返回就绪项 | 大量长连接、事件循环 |

“可读”不等于“一定有完整业务包”；只表示此刻读操作可能不阻塞，仍要按协议缓冲解析。

```text
epoll_wait → 监听fd就绪：accept直到EAGAIN
           → 客户端fd就绪：循环recv，解析完整帧
           → 写事件：尽量发送队列，发完后取消写关注
```

非阻塞模式中 `EAGAIN/EWOULDBLOCK` 是“暂时没数据/暂时写不进”，不是致命错误。边缘触发时尤其要循环读到 `EAGAIN`，否则可能丢失后续通知。

## 云服务器连接：从外到内排查

1. 云主机有正确公网 IP/公网入口；
2. 云安全组允许目标协议和端口；
3. 主机本地防火墙允许端口；
4. 服务绑定地址正确（仅 `127.0.0.1` 外部不可达）；
5. `ss -lntup` 确认确实在监听；
6. 客户端用 `ping`、`nc`、日志和抓包逐层验证。

> [!warning] 安全底线
> 仅开放必要端口，SSH 采用密钥/强认证并及时更新；不要为“连不上”直接开放所有端口或绑定不受控管理接口。
