# C++ 基础与资源管理

## 编译、命名空间、重载与引用

- C++ 文件常为 `.cpp`，用 `g++` 编译；生产构建显式指定标准，例如 `-std=c++17`。交叉编译必须使用目标平台工具链。
- 命名空间防止符号冲突；头文件中避免 `using namespace std;`，实现文件可按需使用。
- 重载依据函数名和参数列表，**不能只靠返回类型**区分。默认参数应只在一个声明处给出，且从右往左连续。
- 引用是已绑定对象的别名：定义时初始化，之后不能改绑。函数参数优先使用 `const T&` 传大对象，既避免拷贝又承诺不修改。

```cpp
void set_level(int& x, int v) { x = v; }        // 可修改调用者
void show(const std::string& s) { std::cout << s; } // 不复制、不修改
```

## `new/delete` 与 RAII

`new` 必须对应 `delete`，`new[]` 必须对应 `delete[]`；混用或漏释放是未定义行为/泄漏来源。更好的默认策略是：**不直接拥有裸 `new` 的结果**。

RAII：资源在对象构造时获得，在析构时自动释放。不仅适用于内存，也适用于 fd、mutex、socket 和设备句柄。

```cpp
class Fd {
 public: explicit Fd(int fd = -1) : fd_(fd) {}
 ~Fd() { if (fd_ >= 0) ::close(fd_); }
 Fd(const Fd&) = delete;                 // 禁止意外双重关闭
 Fd& operator=(const Fd&) = delete;
 private: int fd_;
};
```

## 智能指针：先选所有权

- `std::unique_ptr<T>`：唯一拥有，零/极低额外成本；可移动不可复制，是默认首选。
- `std::shared_ptr<T>`：共享所有权，引用计数有开销；循环引用会泄漏。
- `std::weak_ptr<T>`：不增加计数，用于观察 `shared_ptr` 或打破循环。

> [!warning] 嵌入式建议
> 生命周期清晰时优先对象成员、栈对象、`std::array`/`std::vector`（有容量策略）和 `unique_ptr`。`shared_ptr` 不是“任何指针的安全替换”。
