# C++ IO、异常与并发

## 流与文件

- `std::ifstream` 读文件、`std::ofstream` 写文件、`std::fstream` 双向；先检查 `is_open()` 与流状态。
- `std::getline` 读取整行；`operator>>` 按空白分词。两者混用时要处理残留换行。
- `std::istringstream` 适合把一行文本按字段解析；所有输入都应检查转换是否成功。

```cpp
std::string line; int id{};
if (std::getline(file, line)) {
    std::istringstream in(line);
    if (!(in >> id)) { /* 格式错误 */ }
}
```

## 异常与类型转换

异常适合处理不能在当前位置合理恢复的错误；资源应由 RAII 管理，这样栈展开时仍能释放。资源受限或禁用异常的固件，也必须用返回值/`std::optional`/错误码建立一致路径。

- `static_cast`：明确的常规转换；`dynamic_cast`：多态类型安全下转（需要 RTTI）；`const_cast`：只调整 const 限定，不能让原本 const 对象可安全写入；`reinterpret_cast`：底层位解释，极少使用。
- C 风格强转会混合多种行为，掩盖风险，应避免。

## `std::thread` 与锁

线程对象必须在析构前 `join()` 或 `detach()`；大多数业务线程应 `join`，`detach` 会让生命周期难以管理。

```cpp
std::mutex m; int count = 0;
void work() { std::lock_guard<std::mutex> g(m); ++count; }
std::thread t(work); t.join();
```

`std::lock_guard` 让锁跟随作用域释放，避免异常/提前返回漏解锁。条件变量等待要使用谓词：`cv.wait(lock, []{ return ready; });`；原理与 pthread 相同，必须抵抗虚假唤醒。

> [!question] 自测
> 为什么不用 `detach` 解决“忘记 join”？答：分离后无法可靠等待结束，若线程访问已销毁对象会产生悬空访问；应设计明确的停止、通知与 join 生命周期。
