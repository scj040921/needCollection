# 文件 IO 与显示

## 文件描述符与系统调用

> [!abstract] 核心链路
> `open` 返回文件描述符 `fd` → `read/write` 以字节为单位传输 → `close` 释放内核资源。所有返回值都要检查。

| 调用 | 关键点 |
| --- | --- |
| `open(path, flags, mode)` | 失败为 `-1`；带 `O_CREAT` 时必须给 `mode`；常用 `O_RDONLY/O_WRONLY/O_RDWR` |
| `read(fd, buf, n)` | 返回实际字节数；`0` 表示 EOF；`-1` 看 `errno`；一次不保证读满 |
| `write(fd, buf, n)` | 返回实际写入量；可能部分写，循环补齐才可靠 |
| `lseek(fd, off, whence)` | 改文件偏移；管道/套接字通常不可随机定位 |
| `close(fd)` | 每个成功 `open/socket/accept` 都应恰好关闭一次 |

```c
ssize_t write_all(int fd, const void *buf, size_t len) {
    const char *p = buf;
    size_t done = 0;
    while (done < len) {
        ssize_t n = write(fd, p + done, len - done);
        if (n > 0) done += (size_t)n;
        else if (n < 0 && errno == EINTR) continue;
        else return -1;
    }
    return (ssize_t)done;
}
```

## 标准 IO 与缓冲

- `FILE *` 是 C 库的流对象，内部有缓冲并最终关联 fd；`fopen/fread/fwrite/fgets/fputs/fclose` 是标准 IO。
- `fgets(buf, size, fp)` 最多读 `size-1` 字符并补 `\0`，适合读行；不要把它和“肯定读到完整业务消息”混为一谈。
- `fflush` 刷新用户态标准 IO 缓冲；它不等于数据已经落盘，持久性还涉及内核/设备缓存。
- 不能混用同一文件的底层 IO 和标准 IO，除非严格同步偏移与缓冲。

## `stat`、目录与映射

- `stat` 跟随软链接，`lstat` 查看链接本身；`st_mode` 同时包含文件类型和权限，应用 `S_ISREG/S_ISDIR` 宏判断类型。
- `opendir` → `readdir` → `closedir` 遍历目录。`readdir` 得到的 `d_name` 不是完整路径，需拼接并防止越界。
- `mmap` 将文件/设备映射到进程地址空间，适合大文件、帧缓冲和共享内存；映射长度/偏移需页对齐规则，结束用 `munmap`。

## LCD、帧缓冲与 BMP

- 帧缓冲可看作一块像素数组：先取得宽高、每像素位数、每行步长，再按 `(y * line_length + x * bytes_per_pixel)` 定位。
- RGB 常见分量顺序/位宽不一定相同，不能假设 `uint32_t` 的内存字节序就是屏幕格式。
- BMP 需要读文件头与信息头，检查签名、偏移、宽高、位深与压缩方式；行常按 4 字节对齐，正高度常自底向上存储。

## 动态/静态库

- 静态库 `.a` 链接时复制进目标程序：部署简单、体积较大；动态库 `.so` 运行时共享：节省内存、需处理版本与搜索路径。
- 链接一般写成 `-L目录 -l名字`，`-lfoo` 对应 `libfoo.so` 或 `libfoo.a`；头文件解决“声明”，库文件解决“定义”。

> [!question] 自测
> `read` 返回少于请求长度一定出错吗？不一定：到 EOF、管道/终端/网络可用数据较少等都可能短读。
