# 文件 IO 与显示

## 文件描述符与系统调用

> [!abstract] 核心链路
> `open` 返回文件描述符 `fd` → `read/write` 以字节为单位传输 → `close` 释放内核资源。所有返回值都要检查。

| 调用 | 关键点 |
| --- | --- |
| `open(path, flags, mode)` | 失败为 `-1`；带 `O_CREAT` 时必须给 `mode`；常用 `O_RDONLY/O_WRONLY/O_RDWR` |
| `read(fd, buf, n)` | 返回实际字节数；`0` 表示 EOF；`-1` 看 `errno`；一次不保证读满 |
| `write(fd, buf, n)` | 返回实际写入量；可能部分写，循环补齐才可靠 |
| `lseek(fd, off, whence)` | 改文件偏移；管道/套接字通常不可随机定位 |
| `close(fd)` | 每个成功 `open/socket/accept` 都应恰好关闭一次 |

```c
ssize_t write_all(int fd, const void *buf, size_t len) {
    const char *p = buf;
    size_t done = 0;
    while (done < len) {
        ssize_t n = write(fd, p + done, len - done);
        if (n > 0) done += (size_t)n;
        else if (n < 0 && errno == EINTR) continue;
        else return -1;
    }
    return (ssize_t)done;
}
```

## 标准 IO 与缓冲

- `FILE *` 是 C 库的流对象，内部有缓冲并最终关联 fd；`fopen/fread/fwrite/fgets/fputs/fclose` 是标准 IO。
- `fgets(buf, size, fp)` 最多读 `size-1` 字符并补 `\0`，适合读行；不要把它和“肯定读到完整业务消息”混为一谈。
- `fflush` 刷新用户态标准 IO 缓冲；它不等于数据已经落盘，持久性还涉及内核/设备缓存。
- 不能混用同一文件的底层 IO 和标准 IO，除非严格同步偏移与缓冲。

## `stat`、目录与映射

- `stat` 跟随软链接，`lstat` 查看链接本身；`st_mode` 同时包含文件类型和权限，应用 `S_ISREG/S_ISDIR` 宏判断类型。
- `opendir` → `readdir` → `closedir` 遍历目录。`readdir` 得到的 `d_name` 不是完整路径，需拼接并防止越界。
- `mmap` 将文件/设备映射到进程地址空间，适合大文件、帧缓冲和共享内存；映射长度/偏移需页对齐规则，结束用 `munmap`。

## LCD、帧缓冲与 BMP

- 帧缓冲可看作一块像素数组：先取得宽高、每像素位数、每行步长，再按 `(y * line_length + x * bytes_per_pixel)` 定位。
- RGB 常见分量顺序/位宽不一定相同，不能假设 `uint32_t` 的内存字节序就是屏幕格式。
- BMP 需要读文件头与信息头，检查签名、偏移、宽高、位深与压缩方式；行常按 4 字节对齐，正高度常自底向上存储。

## 动态/静态库

- 静态库 `.a` 链接时复制进目标程序：部署简单、体积较大；动态库 `.so` 运行时共享：节省内存、需处理版本与搜索路径。
- 链接一般写成 `-L目录 -l名字`，`-lfoo` 对应 `libfoo.so` 或 `libfoo.a`；头文件解决“声明”，库文件解决“定义”。

> [!question] 自测
> `read` 返回少于请求长度一定出错吗？不一定：到 EOF、管道/终端/网络可用数据较少等都可能短读。

## 图片题目逐项补全

### 文件描述符、偏移与“特殊文件”

- 文件描述符是进程中指向内核“打开文件描述”的小整数；通常 `0/1/2` 分别为标准输入、标准输出、标准错误。不同 fd 可指向同一打开文件描述并共享偏移。
- 文件当前位置（offset）是下一次读写的位置；`lseek(fd, 0, SEEK_END)` 可定位末尾并返回新位置。带 `O_APPEND` 写入由内核放到末尾，适合追加日志。
- 设备、FIFO、socket 也可通过 fd 使用 `read/write`，但它们的阻塞、是否支持 `lseek`、是否有 EOF 与普通文件不同；接口相同不代表语义相同。

### 标准 IO 函数与三类缓冲

- `fputs(s, fp)` 输出字符串但不自动加换行；`fgets` 成功返回 `buf`，读到 EOF 且未读到任何字符则返回 `NULL`。
- `fread(ptr, size, nmemb, fp)` / `fwrite` 的返回值是**成功读写的元素数**，不是字节数；检查时应与 `nmemb` 比较。
- 全缓冲：缓冲区满才刷新（常见普通文件）；行缓冲：遇 `\n` 或满时刷新（常见终端输出）；无缓冲：每次操作立即交给底层（常见 `stderr`）。实际行为由流和实现决定。

### `stat` 字段、目录与内存映射

- `st_dev` 表示文件所在设备，`st_rdev` 对设备文件表示其所描述设备；普通文件的 `st_rdev` 通常无实际含义。
- `st_mode` 的低位含权限，高位含文件类型；特殊位：`S_ISUID` 以文件属主有效身份执行，`S_ISGID` 以属组身份/目录继承组，sticky bit 目录中通常只允许文件属主/目录属主删除自己的条目（如 `/tmp`）。
- `open` 打开/可创建**文件**，`mkdir` 创建**目录**；两者都受父目录权限和 `umask` 影响。目录遍历略过 `.`、`..`，不要只信 `d_type`，必要时再 `stat`。
- `mmap` 常见于帧缓冲/共享内存：`MAP_SHARED` 修改可回写/对映射者可见，`MAP_PRIVATE` 写时复制；仍需检查 `MAP_FAILED`。

### LCD、BMP 与库的工程化使用

- 获取 LCD 参数通常依赖 framebuffer ioctl：分辨率、`bits_per_pixel`、每行实际字节数和颜色位域；**每行步长可能大于 width × 像素字节数**。
- 设置可视区域常靠虚拟分辨率与偏移（双/多帧缓冲）；绘制写后台缓冲，再切换显示偏移可减少撕裂。切换时要遵循驱动的同步能力。
- BMP 解码先验证 `BM`、像素数据偏移、位深、行对齐和上下方向；24 位 BMP 每像素常为 BGR，不能当 RGB 直接显示。
- 第三方库流程：安装开发包/头文件 → 编译时加入 include 路径和库路径 → 链接 `-lxxx` → 运行时保证 `.so` 可被动态加载。静态库在链接期合入，动态库在运行期解析；排查顺序是“头文件、链接符号、运行库路径”。
