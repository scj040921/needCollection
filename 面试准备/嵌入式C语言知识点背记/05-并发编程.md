# 并发编程

## 进程、线程与生命周期

| 概念 | 记忆 |
| --- | --- |
| 进程 | 资源分配的基本单位，有独立虚拟地址空间；隔离好，切换/通信更重 |
| 线程 | CPU 调度单位，同进程线程共享代码、堆、全局变量和 fd；各自有栈、寄存器状态 |
| `fork()` | 创建子进程；父进程得子 PID，子进程得 0，失败为 -1；现代系统常写时复制 |
| `wait()/waitpid()` | 回收子进程，避免僵尸；`waitpid` 可指定 PID/非阻塞 |
| 僵尸 | 子进程已退出但父未回收，保留退出状态；不是“还在运行” |
| 孤儿 | 父先退出，子进程被收养；不等于僵尸 |

## 线程同步：先找共享状态

- **竞态条件**：结果依赖不可预测的执行交错，例如 `count++` 不是原子操作。
- 互斥锁保护临界区：锁的范围只覆盖共享数据一致性所需代码；所有访问路径使用同一把锁。
- 条件变量用于“等待条件成立”，必须配合 mutex 与 `while (!condition) pthread_cond_wait(...)`，避免虚假唤醒/抢占后条件又变假。
- 读写锁适合读多写少；自旋锁适合持锁极短且不能睡眠的场合，单核或竞争重时可能更差。

```c
pthread_mutex_lock(&lock);
while (queue_empty())
    pthread_cond_wait(&not_empty, &lock);
item = pop();
pthread_mutex_unlock(&lock);
```

> [!warning] 死锁四条件
> 互斥、占有且等待、不可抢占、循环等待。工程上固定加锁顺序、缩小持锁范围、统一异常路径解锁。

## 信号与 IPC

- 信号是异步通知；处理函数只能做异步信号安全的极少操作，常见安全做法是设置 `volatile sig_atomic_t` 标志或写管道，主循环再处理。
- `SIGKILL`、`SIGSTOP` 不能捕获/忽略；`kill(pid, sig)` 是发信号，不等于一定结束进程。
- 匿名管道适合有亲缘关系进程的单向字节流；命名管道可用于无亲缘进程；消息队列保留消息边界；共享内存最快但需自行同步。
- POSIX 信号量用于计数/同步；互斥锁强调所有权（通常谁加锁谁解锁），二者不要混为一谈。

## 定时器

- 相对延时易累计漂移；周期任务常采用“下一个绝对截止时间”计算。
- 定时器回调要短，不阻塞，不直接做复杂 IO；把工作交给线程/事件循环。

> [!question] 自测
> 为什么 `if` 不够而条件变量要用 `while`？醒来后锁虽重新拿到，但条件可能被其他线程先改变，且还可能虚假唤醒。
