# 类、对象与多态

## 构造、析构、拷贝、移动

- 构造函数建立对象不变量；成员初始化顺序按**声明顺序**而非初始化列表书写顺序。
- 析构函数释放资源；基类经指针删除派生对象时，基类析构函数必须是 `virtual`。
- 拷贝构造/赋值复制资源；移动构造/赋值转移资源。若类管理资源，要遵循“零法则”：尽量让成员（如 `vector/unique_ptr`）自动管理；做不到再完整实现/禁用特殊成员函数。

## 继承与组合

- 公有继承表达 **is-a**；组合表达 **has-a**。复用代码时优先组合，只有可替换的真实 is-a 关系才继承。
- 多重继承会带来菱形、初始化和接口冲突复杂度；嵌入式项目中常用纯接口类或组合降低风险。

## 虚函数、抽象类与动态绑定

虚函数通过基类指针/引用调用时，根据对象实际类型选择实现。纯虚函数 `virtual void f() = 0;` 使类成为抽象类，不能直接实例化。

```cpp
struct Sensor {
    virtual ~Sensor() = default;
    virtual int read() = 0;
};
struct AdcSensor final : Sensor {
    int read() override { return 42; }
};
```

`override` 让编译器检查是否真在重写，应该始终写；`final` 表明不再允许继承/重写。

> [!tip] 面试关键
> 多态的价值是“调用方依赖稳定接口，具体设备/算法可替换”。虚函数有间接调用与对象布局成本，极端实时路径可改用模板/函数指针等静态多态。

## 深入讲解：对象构造与资源安全

构造顺序固定为“基类 → 按声明顺序的成员 → 派生类构造函数体”；析构反向。初始化列表的书写顺序不会改变成员实际初始化顺序，因此应与声明顺序一致。构造/析构期间不依赖虚调用执行派生行为：对象此时并非完整派生状态。

若类管理资源，优先让 `std::string`、`vector`、`unique_ptr` 等成员管理资源，即“零法则”。只有直接管理裸资源时才考虑完整实现/禁用拷贝、移动、赋值和析构等特殊成员函数。

## 继承设计检查

只有 `Derived` 能无条件替换 `Base`（行为语义也正确）才使用公有继承；复用实现优先组合。基类若可能经基类指针删除，析构函数必须 `virtual`；重写函数总加 `override`，让编译器发现签名不一致。
