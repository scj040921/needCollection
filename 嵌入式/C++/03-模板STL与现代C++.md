# 模板、STL 与现代 C++

## 模板与泛型

函数/类模板将“类型”参数化，编译期生成具体版本；好处是复用与类型检查，代价是编译错误长、二进制可能膨胀。模板定义通常放头文件。

- 可变参数模板用参数包表示零到多个参数；C++17 折叠表达式可把重复运算简化，例如 `(args + ...)`。
- `std::forward<T>` 用于转发引用场景，保留左值/右值类别；只有写包装器/通用转发时才需要，不要把它当普通移动工具。

## 容器与算法：按数据访问方式选

| 容器 | 适合 | 不适合 |
| --- | --- | --- |
| `std::array` | 固定容量、无堆分配 | 运行时大小 |
| `std::vector` | 连续存储、随机访问 | 指针/迭代器频繁失效的场景 |
| `std::deque` | 两端高效插删 | 需要连续内存 |
| `std::list` | 已知位置插删 | 高频随机访问/缓存敏感 |
| `std::map/unordered_map` | 有序查找/平均快速查找 | 不设容量与哈希策略的实时热路径 |

`vector` 扩容会移动元素并使指针、引用、迭代器失效；若最大数量可估，先 `reserve`。算法优先写 `std::find`、`std::sort`、`std::for_each`，减少手写循环边界错误。

## 可调用对象与运算符重载

函数、函数指针、lambda、重载 `operator()` 的对象都可调用；`std::function` 统一包装但可能有额外分配/间接调用，嵌入式热路径可用模板参数或函数指针。

运算符重载必须保持直觉语义：`operator+` 不应修改左操作数，`operator==` 应满足自反/对称/传递。不要为了“炫技”重载让读者猜不出含义。

## 深入讲解：模板与编译期实例化

模板在编译期按实际类型生成代码，而非运行时万能分支；定义通常放 `.hpp`，否则其他编译单元实例化时看不到定义。泛型函数应明确所需能力，例如下面要求 `T` 可比较；返回引用只适合参数对象寿命足够长。

```cpp
template<class T>
const T& max_value(const T& a, const T& b) { return a < b ? b : a; }
```

## 深入讲解：`vector` 的容量陷阱

`size` 是元素数，`capacity` 是当前可容纳量；`reserve(n)` 只预留空间，`resize(n)` 会创建元素。扩容可能移动底层数组，所有旧指针、引用和迭代器都可能失效。

嵌入式若不能接受运行时分配，使用 `std::array`/固定环形队列；若上限已知，在初始化阶段 `reserve(MAX)` 并拒绝超过上限。异步 lambda 不应以 `[&]` 捕获即将离开作用域的局部变量；回调晚执行会悬空。
