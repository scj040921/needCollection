# 事件驱动网络服务架构

> [!abstract] 从“类名”理解职责
> 将 fd 就绪、连接生命周期、协议解析、业务分发和房间/会话状态拆开。每个类只维护一类不变量，事件循环只调度，不承载业务细节。

## 推荐职责划分

```text
Acceptor → EventLoop → IEventHandler / TcpConnection
                         ↓
                 ClientSession → MessageDispatcher → RoomManager
                         ↓               ↓
                    SessionManager    ProtocolMessage(JSON)
```

| 组件 | 只负责什么 | 关键 C++ 点 |
| --- | --- | --- |
| `EventLoop` | `epoll` 等待、注册/移除 fd、运行/停止 | `atomic<bool>` 停止标志；禁止拷贝 |
| `IEventHandler` | 声明读写/错误事件接口 | 纯虚函数 + 虚析构 |
| `Acceptor` | 监听 fd、接收新连接 | 非阻塞 `accept`；回调交给会话层 |
| `TcpConnection` | 一个 TCP fd 的读写缓冲与关闭 | RAII 管理 fd；必要时 `enable_shared_from_this` |
| `ProtocolMessage` | 消息类型和序列化/反序列化 | 长度/字段校验；JSON 不是可信输入 |
| `MessageDispatcher` | 消息类型 → 处理函数 | `unordered_map<type, handler>`；未知类型默认拒绝 |
| `Room/SessionManager` | 业务状态与索引 | 明确锁策略和对象所有权 |
| `Logger` | 结构化日志输出 | C++11 局部静态单例初始化线程安全，但日志写入仍需同步 |

## 事件接口的最小形态

```cpp
struct IEventHandler {
    virtual ~IEventHandler() = default;
    virtual void on_readable() = 0;
    virtual void on_writable() = 0;
    virtual void on_error() = 0;
};
```

事件回调里必须处理短读、半包和 `EAGAIN`；不得把“读到一次”直接当作“收齐一条 JSON”。写事件只在发送队列非空时关注，队列清空后取消关注，避免空转。

## 生命周期与并发陷阱

- 若 handler 被 event loop 保存回调，`this` 的生命周期必须覆盖回调；需要异步延长生命周期时使用 `shared_from_this()`，但避免闭环引用。
- 连接关闭顺序：从 poller 移除 fd → 取消回调/定时器 → 清理业务索引 → 关闭 fd。顺序不一致容易触发 use-after-free。
- 房间/会话管理器如果跨线程访问，定义“单线程事件循环拥有”或“互斥锁保护”的单一规则；不要部分访问加锁、部分不加。

> [!tip] 嵌入式迁移
> 资源较少时可保留同样职责边界，但缩小为单线程 `poll` 循环 + 固定容量消息队列；架构思想不依赖大型服务器或动态扩容。

## 深入讲解：一次消息如何穿过各层

`Acceptor` 接到新 fd 后创建 `ClientSession` 并注册给 `EventLoop`；session 把 TCP 字节累积成完整 `ProtocolMessage`；`MessageDispatcher` 按类型选择处理器；处理器访问 `RoomManager/SessionManager`；结果再进入 session 的发送队列，由可写事件逐步发出。

这样分层后，协议解析可脱离 socket 做单元测试，房间管理可脱离网络做测试。关闭连接的推荐顺序：先从 poller 移除 fd，再取消定时器/回调，然后解除业务索引，最后关闭 fd 和释放对象。

异步回调捕获裸 `this` 容易在连接提前销毁后 use-after-free。需要延长到回调结束时可捕获 `shared_from_this()`；长期回调/定时器应捕获 `weak_ptr` 并在执行时 `lock()`，避免循环引用让连接永不释放。
