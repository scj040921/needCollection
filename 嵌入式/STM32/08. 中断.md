# 一、中断的基本概念
## 1. 什么是中断
正在处理的任务因为收到中断请求而暂时停止正在进行的任务去处理中断事件的过程就是中断
## 2. 中断的分类
- STM32F103的异常有10个，外部中断有60个，除了个别异常的优先级被定死外，其它异常的优先级都是可编程的
- **内核异常**：
	- 由ARM Cortex-M内核机制产生或管理：
		- SysTick：滴答定时器中断，用于定时。
		- HardFault：程序出现严重错误时触发。
		- PendSV：常用于操作系统任务切换。
- **外部中断（IRQ）**
	- 由片上外设等发出的中断请求：
		- EXTI 中断：按下按键时触发。
		- TIM 中断：定时器计数完成时触发。
		- USART 中断：串口收到数据时触发。
		- ADC 中断：模数转换完成时触发。
- **可屏蔽中断**：可以通过中断控制机制禁止响应GPIO、USART、TIM等
- **不可屏蔽中断**：不能通过普通中断屏蔽机制禁止
- STM32通过NVIC（嵌套向量中断控制器）管理中断的使能和优先级
- 中断优先级的数值越小优先级越高
## 3. 默认的中断服务程序
- 每个中断源都会有一个唯一对应的中断服务函数
- 对所有的异常和中断，都提供了一个默认实现：一个什么都不做的无限循环
- 它们都被标记为WEAK，也就是说连接器会有心啊使用程序员自己实现的同名函数
## 4. NVIC
- 嵌套向量中断控制器，是内核的一个内置单元，用于集中管理所有的异常和中断，提供了强大且灵活的中断管理功能
### 中断优先级的寄存器
- 这是NVIC最核心的管理功能。为每个中断源分配一个可编程的优先级，用于仲裁当多个中断同时发生时的处理顺序
- 中断优先级由一个8位的寄存器字段表示，但通常只用其中的高四位。![[Pasted image 20261022162239.png]]
### 优先级分组
- 优先级分组的核心思想就是将这四个比特位，划分给“抢占优先级”和“子优先级”两部分
- 分组0：抢占0，子4，0级抢占优先级16级子优先级
- 分组1：抢占1，子3，2级抢占优先级8级子优先级
- 分组2：抢占2，子2，4级抢占优先级4级子优先级
- 分组3：抢占3，子1，8级抢占优先级，2级子优先级
- 分组4：抢占4，子0，16级抢占优先级，0级子优先级
### 仲裁规则
1. 无论哪一种优先级，都是数值越小优先级越高
2. 高抢占优先级可以打断正在进行的低抢占优先级的中断。抢占优先级若相同，则不会出现抢占的过程
3. 抢占优先级相同的中断，高子优先级不可以打断正在运行的低子优先级中断
4. 抢占优先级相同的中断同时请求CPU，先响应子优先级高的
5. 抢占优先级和子优先级都相同的中断，按照硬件内部固定的优先级响应
## NVIC配置中断的函数
- 设置优先级分组：void HAL_NVIC_SetPriorityGrouping(uint32_t PriorityGroup);
	- 程序只需要中断分组一次即可，以后不用重复中断分组
- 设置中断源、优先级等函数：
	- void HAL_NVIC_SetPriority(IRQn_Type IRQn, uint32_t PreemptPriority, uint32_t SubPriority);// 设置中断源、优先级
	- void HAL_NVIC_EnableIRQ(IRQn_Type IRQn); // 使能中断源
# 二、 EXTI外部中断
## 1. EXTI简介
- EXTI是STM32的外部中断/事件控制器
- EXTI可以检测GPIO引脚上的电平变化，当满足触发条件时，让CPU执行相应的中断程序
- EXTI外设通过对输入信号的上升沿和下降沿的检测解决轮询效率低下的问题
- CPU正常执行程序，当某个GPIO引脚上出现规定的边沿时，硬件自动发出中断请求，CPU暂停当前代码去执行一段中断服务函数，执行完返回原处继续执行
- 优势：
	- 实时性：从引脚跳变到 CPU 响应只需要十几个时钟周期（本工程 72MHz 下不足 1 微秒），远超轮询的实时性。
	- 省电 / 高效：主循环可以去做别的事（甚至进入低功耗休眠），不必空转查询。
	- 不漏事件：边沿检测电路会把短时间内出现的脉冲"锁存"在挂起寄存器里，即使 CPU 当时在忙，事件也不会丢失。
## 2. EXTI的工作模式
1. **中断模式**：
	- 触发CPU中断执行ISR
	- 用于需要立刻处理的事件
2. **事件模式**：
	- 唤醒CPU但是不执行ISR
	- 用于低功耗场景
## 3. EXTI的触发方式
- **上升沿触发**：信号从低电平到高电平
- **下降沿触发**：信号从高电平到低电平
- **双边沿触发**：上升沿和下降沿都触发
