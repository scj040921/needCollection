# 1.库相关的基本概念
## 编译过程
- 编译一般会经历如下四个步骤：
	1. 预处理：解释并展开源程序中的所有预处理指令，生成.i文件
	2. 编译：词法和语法的分析，生成对应硬件平台的汇编语言文件，生成.s文件
	3. 汇编：将汇编语言文件，翻译为对应处理器的二进制机器码，此时生成.o文件
	4. 链接：将多个.o文件合并成一个不带后缀的可执行文件
## ELF格式
### 概述
- 在链接这一步时，合并之前的.o文件是ELF格式，合并后也是ELF格式
- ELF的全称是可执行可链接格式，由多个不同的段组成
- ELF格式的合并，实际上就是将多个文件中各自对应的段合并在一起，形成一个统一的ELF文件。
- 在合并的过程中需要对.o文件中的静态数据、函数入口的地址做统一分配和管理，这个过程叫做重定位，因此未链接的.o文件也被称为可重定位文件，经过合并相同段的文件是可执行文件
- 库的本义是图书馆，库文件就是一个由很多.o文件堆积起来的集合
### 相关命令
- readelf可以用来查看ELF格式文件的具体细节
```
# 查看文件格式头部信息
gec@ubuntu:~$ readelf -h a.out

# 查看各个section信息
gec@ubuntu:~$ readelf -S a.out

# 查看符号表
gec@ubuntu:~$ readelf -s a.out
```
- ldd可以用来查看ELF格式文件的动态库依赖关系
```
gec@ubuntu:~$ ldd a.out
```
## 库的基本概念
- 库文件分为两类：静态库和动态库
	- 静态库：libx.a
	- 动态库：liby.so
- 库文件的命名遵循这样的规范：
	- lib库名.后缀
- lib是任何库文件都必须要有的前缀，库名是库文件真正的名称
- 静态库后缀：.a（archive,意思是档案）
- 动态库后缀：.so（share object,共享对象）
# 2.静态库的制作与应用
## 静态库的制作
- **步骤**：
	1. 制作.o原料
	```
	gec@ubuntu:~$ gcc a.c -o a.o -c
	gec@ubuntu:~$ gcc b.c -o b.o -c
	```
	2. 将.o文件合并成一个静态库
```
gec@ubuntu:~$ ar crs libx.a a.o b.o
```
## 静态库的常见操作
- 查看静态库中的.o列表
	- ar t libx.a
- 删除静态库中的.o文件
	- ar d libx.a
- 向动态库中增加.o文件
	- ar r libx.a b.o
- 提取静态库中的.o文件
	- ar x libx.a
## 静态库的使用
-  编写a.c
	```
	#include <stdio.h>
	
	void someFunc(void)
	{
	printf("实现某个功能模块...\n");
	}
	```
- 将a.c制作为静态库
```
gec@ubuntu:~$ gcc a.c -o a.o -c
gec@ubuntu:~$ ar crs libx.a a.o
```
- 在有需要的地方链接该库
```
#include <stdio.h>
#include "a.h"

int main(int argc, char const *argv[])
{
    someFunc();
    return 0;
}
```
- 编译并运行
```
gec@ubuntu:~$ gcc main.c -L/path/to/lib/ -lx -o main
gec@ubuntu:~$ ./main
实现某个功能模块...
gec@ubuntu:~$
```
### 注意
- 编译语句中的-L/path/to/lib/ 指明库文件的具体位置，否则系统找不到该库文件
- 编译语句中的-lx指明库文件的名称，不包含前后缀
- 对于静态库而言，编译链接时会将主文件需要的库代码复制一份到最终的执行文件中，导致静态库有如下特质
	- 执行程序在编译之后与静态库脱离关系，其执行也不依赖于静态库
	- 执行程序时不依赖静态库，因此也省去了运行时动态
## 库中重名符号
- 符号指的是函数名、变量名，当库中不同的.o文件有重名的符号时，被调用的版本则以他们在库中排列在前面的为准
## 多个库的相互依赖
- 当编译链接多个库，且这些库之间有依赖关系时，被依赖的基础库要放在编译语句后面
- 以上结论对动态库、静态库都适用
# 3.动态库的制作与应用
## 动态库的基本概念
- **静态库**：
	- **原理**：编译时，库中的代码将会被复制到一个程序中
	- **优点**：程序不依赖于库，执行效率高
	- **缺点**：浪费存储空间、无法对用户升级迭代
- **动态库**：
	- **原理**：编译时，程序仅确认库中功能模块的匹配关系，并未复制
	- **缺点**：程序依赖库，执行效率低
	- **优点**：节省存储空间，方便对用户升级迭代
## 动态库的命名
- 对于动态库而言，除了前缀库名后缀，在后缀后面还经常会带着版本号
- 当动态库迭代升级时，其版本号会发生相应改变
```
lib库名.so.主版本号.次版本号.修订版本号
```
- 修订版本号的更迭会比较频繁，次版本号次之，主版本号再次之。
- 为了避免每次版本号的更改而重新编译，动态库一般会用一个只带主版本号的符号来链接程序，这样只要主版本号不变，都不需要重新编译
## 动态库的制作
- 将.c编译生成.o
- 将.o编译生成动态库
## 动态库的使用
- -L选项后边跟着动态库所在的路径
- -l后面跟着动态库的名称
## 运行时链接
- 动态库的最大特征，就是编译链接后的程序并不包含动态库的代码，这些程序会在运行时动态的去寻找并定位其所依赖的库文件中的模块
