# 1. 基本概念
## 文件的概念
- **狭义**：普通的文本文件或二进制文件
- **广义**：几乎所有可操作的设备或接口
## Linux中的文件分类
1. **普通文件**：存在外部存储器中，用于存储普通数据（-）
2. **目录文件**：用于存放目录项，是文件系统管理的重要文件类型（d）
3. **管道文件**：一种用于进程间通信的特殊文件，也称为命名管道FIFO(p)
4. **套接字文件**：用于网络间通信的特殊文件(s)
5. **链接文件**：用于间接访问另外一个目标文件(l)
6. **字符设备文件**：字符设备在应用层的访问接口(c)
7. **块设备文件**：块设备在应用层的访问接口(b)
## 系统IO与标准IO
- 对文件的操作，基本上就是输入输出，因此也一般称为IO接口
- 在操作系统层面上，专门针对文件的IO接口就被称为系统IO，是众多系统调用中专用于文件操作的一部分接口
- 在标准库的层面上，专门针对文件的IO接口就是标准IO，是众多标准函数中用于文件操作的一部分接口
- 标准IO实际上是对系统IO的封装，系统IO是更接近底层的接口
## 如何选择系统IO与标准IO
- **系统IO**
	1. 由操作系统直接提供的函数接口，特点是简单功能单一
	2. 没有提供缓冲区，因此对海量数据的操作效率较低
	3. 套接字、设备文件的访问只能使用系统IO
- **标准IO**
	1. 由标准c库提供的函数接口，特点是功能丰富
	2. 有缓冲区，海量文件处理效率高
	3. 编程开发中尽量选择标准IO
# 2. 系统IO基本API
## 文件的打开与关闭
### 打开文件
- **功能**：打开一个指定的文件并获得文件描述符，或者创建一个新文件
- **原型**：
	- int open(const char \*pathname,int flags);
	- int open(const char \*pathname,int flags,mode_t mode)
- **参数**：
	- pathname：即将要打开的文件
	- flags：
		- O_RDONLY:只读方式打开文件
		- O_WRONLY：只写方式打开文件
		- O_RDWR:读写方式打开文件
		- O_CREAT:如果文件不存在，则创建该文件
		- O_EXCL:如果使用O_CTEAT选项且该文件存在，则返回错误消息
		- O_NOCTTY:当文件为终端时，阻止该终端成为进程的控制终端
		- O_TRUNC:如文件已存在则删除文件中原有数据
		- O_APPEND:以追加方式打开文件，需配合写模式可追加文件
	- mode:如果文件被新建，指定其权限为mode（八进制表示法）
- **返回值**
	- 成功：大于等于0的整数
	- 失败：-1
- **关键点**
	- open函数有两个版本，一个有两个参数一个有三个参数
	- 当打开一个已存在的文件时，指定两个参数即可
	- 当创建一个新文件时，需要指定第三个参数指定新文件的权限，否则系文件的权限时随机值
	- 模式flags，可以使用位或的方式来同时指定多个模式
	- 模式flags中，O_NOTTCY主要用在后台精灵进程，组织这些精灵进程拥有控制终端
### 关闭文件
- **功能**:关闭文件并释放相应资源
- **原型**:int close(int fd);
- **参数**：fd，即将要关闭的文件的描述符
- **返回值**
	- 成功：0
	- 失败：-1
- **关键点**
	- 重复关闭一个已经关闭了的文件或者尚未打开的文件时安全的
	- 当不在使用一个文件时，应当关闭该文件，防止系统资源浪费
## 标准库函数的错误处理
- 在所有的库函数中，如果调用过程出错了，函数除了会返回一个特定的数据来告诉用户调用失效之外，还会去修改一个全局错误码，来帮助开发者确认错误
- **关键点**：
	- 如果库函数、系统函数调用出错了，全局错误码会随之改变
	- 如果库函数、系统调用没有出错，全局错误码不会改变
	- 一个库函数、系统调用出错后，若未及时处理错误码，则错误码可能会被随后的其它函数修改
- **提取错误码的两种方法**
	- 使用perror()，直接输出用户信息和错误信息
	- 使用strerror()，返回错误信息交给用户自行处理
	- 一般而言，perror()用起来更方便，但strerror()可以用来输出一些更加灵活的信息。
