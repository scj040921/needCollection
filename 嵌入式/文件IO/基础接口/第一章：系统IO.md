# 1. 基本概念
## 文件的概念
- **狭义**：普通的文本文件或二进制文件
- **广义**：几乎所有可操作的设备或接口
## Linux中的文件分类
1. **普通文件**：存在外部存储器中，用于存储普通数据（-）
2. **目录文件**：用于存放目录项，是文件系统管理的重要文件类型（d）
3. **管道文件**：一种用于进程间通信的特殊文件，也称为命名管道FIFO(p)
4. **套接字文件**：用于网络间通信的特殊文件(s)
5. **链接文件**：用于间接访问另外一个目标文件(l)
6. **字符设备文件**：字符设备在应用层的访问接口(c)
7. **块设备文件**：块设备在应用层的访问接口(b)
## 系统IO与标准IO
- 对文件的操作，基本上就是输入输出，因此也一般称为IO接口
- 在操作系统层面上，专门针对文件的IO接口就被称为系统IO，是众多系统调用中专用于文件操作的一部分接口
- 在标准库的层面上，专门针对文件的IO接口就是标准IO，是众多标准函数中用于文件操作的一部分接口
- 标准IO实际上是对系统IO的封装，系统IO是更接近底层的接口
## 如何选择系统IO与标准IO
- **系统IO**
	1. 由操作系统直接提供的函数接口，特点是简单功能单一
	2. 没有提供缓冲区，因此对海量数据的操作效率较低
	3. 套接字、设备文件的访问只能使用系统IO
- **标准IO**
	1. 由标准c库提供的函数接口，特点是功能丰富
	2. 有缓冲区，海量文件处理效率高
	3. 编程开发中尽量选择标准IO
# 2. 系统IO基本API
## 文件的打开与关闭
### 打开文件
- **功能**：打开一个指定的文件并获得文件描述符，或者创建一个新文件
- **原型**：
	- int open(const char \*pathname,int flags);
	- int open(const char \*pathname,int flags,mode_t mode)
- **参数**：
	- pathname：即将要打开的文件
	- flags：
		- O_RDONLY:只读方式打开文件
		- O_WRONLY：只写方式打开文件
		- O_RDWR:读写方式打开文件
		- O_CREAT:如果文件不存在，则创建该文件
		- O_EXCL:如果使用O_CTEAT选项且该文件存在，则返回错误消息
		- O_NOCTTY:当文件为终端时，阻止该终端成为进程的控制终端
		- O_TRUNC:如文件已存在则删除文件中原有数据
		- O_APPEND:以追加方式打开文件，需配合写模式可追加文件
	- mode:如果文件被新建，指定其权限为mode（八进制表示法）
- **返回值**
	- 成功：大于等于0的整数
	- 失败：-1
- **关键点**
	- open函数有两个版本，一个有两个参数一个有三个参数
	- 当打开一个已存在的文件时，指定两个参数即可
	- 当创建一个新文件时，需要指定第三个参数指定新文件的权限，否则系文件的权限时随机值
	- 模式flags，可以使用位或的方式来同时指定多个模式
	- 模式flags中，O_NOTTCY主要用在后台精灵进程，组织这些精灵进程拥有控制终端
### 关闭文件
- **功能**:关闭文件并释放相应资源
- **原型**:int close(int fd);
- **参数**：fd，即将要关闭的文件的描述符
- **返回值**
	- 成功：0
	- 失败：-1
- **关键点**
	- 重复关闭一个已经关闭了的文件或者尚未打开的文件时安全的
	- 当不在使用一个文件时，应当关闭该文件，防止系统资源浪费
## 标准库函数的错误处理
- 在所有的库函数中，如果调用过程出错了，函数除了会返回一个特定的数据来告诉用户调用失效之外，还会去修改一个全局错误码，来帮助开发者确认错误
- **关键点**：
	- 如果库函数、系统函数调用出错了，全局错误码会随之改变
	- 如果库函数、系统调用没有出错，全局错误码不会改变
	- 一个库函数、系统调用出错后，若未及时处理错误码，则错误码可能会被随后的其它函数修改
- **提取错误码的两种方法**
	- 使用perror()，直接输出用户信息和错误信息
	- 使用strerror()，返回错误信息交给用户自行处理
	- 一般而言，perror()用起来更方便，但strerror()可以用来输出一些更加灵活的信息。
## 文件描述符本质
- 函数open()的返回值类型是int，本质上是内核中fd_attay数组的下标
- 打开文件时，内核产生一个指向file{}的指针，并将该指针放入一个位于file_struct{}中的数组fd_array[]中，而该指针所指的数组的下标就被返回给用户，称这个下标为文件描述符。
- **结论**
	- 文件描述符从0开始，每打开一个新的文件，就产生一个新的文件描述符
	- 可以重复打开同一个文件，每次打开文件都会使内核产生系列结构体，并得到不同的文件描述符
	- 由于系统在每个进程开始运行时都默认打开了一次键盘两次屏幕，因此0、1、2描述符分别代表标准输入、标准输出和标准出错三个文件
## 文件的读写操作
### 读操作
- **功能**：从指定文件中读取数据 
- **原型**：ssize_t read(int fd,void \*buf,size_t count)
- **参数**：
	- fd：从文件fd中读取数据
	- buf：指向存放读到数据的缓冲区
	- count：要读取的字节数
- **返回值**
	- 成功：实际读取的字节数
	- 失败：-1
- **关键点**：
	- 实际读到的字节数小于等于count
	- 读取普通文件时，如果读到了文件末尾，read()会返回0
	- 读取管道文件时，如果管道中没有数据，read()会默认阻塞
### 写操作
- **功能**：将数据写入指定的文件
- **原型**：ssize_t write(int fd,const void \*buf,size_t count);
- **参数**
	- fd：将数据写入到fd文件中
	- buf：指向即将要写入的数据
	- count：要写入的字节数
- **返回值**
	- 成功：实际写入的字节数
	- 失败：-1
## 文件的读写位置
- 对文件进行读写操作时，系统会记录操作的位置
- **注意**
	- 每open一个文件，系统就会维护一套包括文件操作位置在内的相关信息
	- 对同一个文件描述符进行读写操作时，使用的时同一套文件信息，影响的是同一个位置参数
	- 对同一个文件的不同描述符进行读写操作时，使用的是不同的文件信息，彼此之间相互独立
## 读写位置的设置
- 对文件进行常规的读写操作时，系统会自动调整读写位置
- **功能**：调整文件位置偏移量
- **原型**：off_t lseek(int fd,off_t offset,int whence);
- **参数**：
	- fd：要调整位置偏移量的文件的描述符
	- offset：新位置便宜量相对基准点的偏移
	- whence:基准点
		- SEEK_SET:文件开头处
		- SEEK_CUR:当前位置
		- SEEK_END:文件末尾处
- **返回值**
	- 成功：新文件的位置偏移量
	- 失败：-1
- **关键点**
	- lseek函数可以将文件位置调整到任意的位置，可以是已有数据的地方，也可以是没有数据的地方，假设调整到文件末尾之后的某个位置，文件将会形成空洞
	- lseek只能对普通文件调整文件位置，不能对管道文件调整
	- lseek的返回值的单位是字节
# 3.系统IO常用API
## ioctl()
- 该函数用于沟通应用层和驱动层
- **功能**：文件控制
- **原型**：int ioctl(int d,int request,...);
- **参数**
	- d：要控制的文件的描述符
	- request：针对不同文件的各种控制命令字
	- 变参：根据不同的命令字而不同
- **返回值**
	- 成功：0或非负整数
	- 失败：-1
- **关键点**：
	- 底层驱动开发者可以自定义命令字
	- 对于某些常见的硬件设备的常见功能，系统提供了规范的命令字
## dup()与dup2()
 - 两个函数都具有复制文件描述符的功能
 - **原型**
	 - int dup(int oldfd);
	 - int dup2(int oldfd,int newfd);
 - **参数**
	 - oldfd：要复制的文件描述符
	 - newfd：指定的新的文件描述符
 - **返回值**
	 - 成功：新的文件描述符
