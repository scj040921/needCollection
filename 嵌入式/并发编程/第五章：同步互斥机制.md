# 01.互斥锁与读写锁
## 基本概念
- 互斥是指控制两个进程是指相互排斥，不同时运行
- 同步是指控制两个进度使之有先有后，次序可控
## 互斥锁
### 基本逻辑
- 是使得多线程之间互斥运行的最简单的方法
- 互斥锁的本质是一个二值信号量，因此当其中一个线程获取之后其余线程就无法再次获取，效果相当于给相关的资源上了锁，直到使用者主动解锁，其它线程才有机会获得
### 函数接口
- **定义**：
	- pthread_mutex_t m;
	- 由于互斥锁要被多条线程使用，因此一般会定义为全局变量
- **初始化与销毁**：
	- 未经初始化的互斥锁无法使用
	- 静态初始化：定义同时赋予其初始值
	- 动态初始化：使用pthread_mutex_init()，给互斥锁分配动态内存并赋予初始值，这种情形下的互斥锁在使用完后需要显示的释放资源
	- 静态初始化互斥锁不涉及动态内存，不需要显示释放互斥锁资源
	- 
		// 初始化互斥锁
		int pthread_mutex_init(pthread_mutex_t \*restrict mutex,
		                       const pthread_mutexattr_t \*restrict attr);
		
		// 销毁互斥锁
		int pthread_mutex_destroy(pthread_mutex_t \*mutex);
	- 接口说明：
		- mutex：互斥锁
		- attr：互斥锁属性
- **加锁与解锁**：
	- 加锁：pthread_mutex_lock(&m);
	- 解锁：pthread_mutex_unlock(&m);
## 读写锁
### 基本逻辑
- 互斥锁不对加锁对象进行区别，读写场景下效率低，因此要对资源的读写操作进行区分：读操作可以多任务并发执行，只有写操作会进行恰当的互斥
- **定义**：
	- 读写锁也是一种特殊的变量
	- pthread_rwlock_t rw;
- **初始化**：
	- 静态初始化 ：pthread_rwlock_t rw = PTHREAD_RWLOCK_INITIALIZER;
	- 动态初始化及销毁：
		int pthread_rwlock_init(pthread_rwlock_t \*restrict rwlock,
		                        const pthread_rwlockattr_t \*restrict attr);
		
		int pthread_rwlock_destroy(pthread_rwlock_t \*rwlock);
- **加锁**：
	- 读操作可以共享，因此多条线程可以对同一个读写锁加多重读锁
	- 写操作天然互斥，因此多条线程只能有一个拥有写锁（写锁与读锁也互斥)
- 读锁
	1，阻塞版本
	int pthread_rwlock_rdlock(pthread_rwlock_t \*rwlock);
	2，非阻塞版本
	int pthread_rwlock_tryrdlock(pthread_rwlock_t \*rwlock);
-  写锁
	1，阻塞版本
	int pthread_rwlock_wrlock(pthread_rwlock_t \*rwlock);
	2，非阻塞版本
	int pthread_rwlock_trywrlock(pthread_rwlock_t \*rwlock);
# 02.POSIX信号量
## 基本概念
- POSIX匿名信号量
	- 通常用在线程间
	- 只存在于内存，在文件系统不可见
- POSIX具名信号量
	- 通常用在进程间
	- 存在于文件系统/dev/shm中，可被不同进程操作
## POSIX匿名信号量
### 定义
- sem_t s;
### 初始化
- int sem_init(sem_t \*sem,int pshared,unsigned int value);
- 接口说明：
	- sem：待初始化信号量指针
	- pshared：指定信号量的作用范围
		- 0：作用于进程内的线程间
		- 非0：作用于进程间
	- value：信号量的初始值
### p/v操作
- p操作：int sem_wait(sem_t \*sem);
- v操作：int sem_post(sem_t \*sem);
- P操作即申请资源，因此P操作sem_t wait()在资源不足时会阻塞，而v操作永远不会阻塞
## POSIX具名信号量
- 主要用于多进程间的同步和互斥，p/v操作与匿名版本的操作相同，但是存在于文件系统中，可以被系统中任意有权限的进程打开
- POSIX具名信号量使用如下接口创建：
	- sem_t \*sem_open(const char \*name,int oflag);
	- sem_t \*sem_open(const char \*name,int oflag,mode,unsigned int value);
- 初建时需要指定文件权限mode和初始值value，后续再打开时则无需指定
- POSIX具名信号量和文件操作类似，打开之后会在内核需要时对其维护，因此再不需要时应予以关闭
- 即使所有的进程都关闭了信号量且退出，具名信号量对应的文件时不会消失的，并且会保存所有p/v操作后的值
# 03.条件量
## 基本概念
- 程序的执行通常要满足一些条件，条件不成熟时任务进入睡眠阻塞等待，条件成熟时被唤醒。任何时候都必须以互斥的形式对条件进行访问。条件量就是解决上述问题的逻辑机制。
- 条件时程序运行需要的前提条件，条件量是一种同步互斥变量
- 条件量的逻辑：
	1. 进行条件判断前先加锁，防止并发访问
	2. 成功加锁后判断条件是否允许：
		1. 若允许则直接操纵临界资源，然后释放锁
		2. 若不允许，则进入条件量的等待队列中睡眠，同时释放锁
	3. 在条件量中睡眠的的任务，可以被其他任务唤醒，唤醒时重新判断条件是否允许程序继续执行
## 条件量的使用
- 一般与互斥锁配套使用，互斥锁锁住临界资源，条件量进行阻塞睡眠和唤醒
