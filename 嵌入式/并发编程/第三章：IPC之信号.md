# 01.标准信号处理
## 信号基本概念
- 相对于其它的IPC而言其最大的特点是异步性
## 标准信号处理
- 信号可以分为两大类，一类是常用的标准信号，另一类就是后面引入的实时信号
- 标准信号的特点：
	- 不排队，信号的响应会相互嵌套
	- 如果目标进程没有及时响应，那么随后到达的相同信号将会被丢弃
	- 每个信号都对应一个系统事件
	- 在进程的挂起信号中，进程会优先响应实时信号
- 实时信号也称为可靠信号，有如下特点：
	- 实时信号的响应次序按接受顺序排队，不嵌套
	- 即使相同的实时信号被同时发送多次也不会被丢弃，而会依次挨个响应
	- 实时信号没有特殊的系统事件与之对应
### 信号的生命周期
- **信号的产生**：
	信号即可以由特定的事件产生，也可由用户主动发起，但不论是那种信号都是触发了内核的信号发生器，并向特定进程递送的过程
- **信号的挂起**：
	每个进程都保留有一个挂起信号集，所有被发送到这个进程的信号首先被放入这个信号集，挂起信号集存储了进程待处理的信号，这些信号必须要等到进程被系统调度，真正执行的时候才能被进一步响应
- **信号的响应**：
	信号的响应有以下四种方式：
		1.  屏蔽：也称为阻塞，即延缓对信号的响应，直到解除对该信号的屏蔽为止
		2.  捕捉：执行一个预先设置的与信号量相关联的响应函数
		3.  默认：按信号默认的情况处理
		4.  忽略：直接丢弃该信号
### 信号的产生
- 除了由特定事件触发的信号外，信号的产生均可由用户调用如下接口来主动触发
- int kill(pid_t pid,int sig);
- pid是接收信号的进程PID
- sig是信号的编号
- 在终端中也可以直接使用kill命令来发送信号
### 信号的响应方式
#### 信号的屏蔽
- 屏蔽信号实际上就是对信号的暂缓处理
- int sigprocmask(int how,const sigset_t \*set,sigset_t \*oldset);
- how：操作命令字，比如阻塞解除阻塞等
- set：当前要操作的信号集
- oldset：若为非空，则将原有阻塞信号集保留到该oldset中
- 该函数操作的是信号集而非单个信号，这意味着可以同时对多个信号设置阻塞或解除阻塞
- 操作命令字可以有以下取值：
	- SIG_BLOCK：阻塞set中的信号，原有正在阻塞的信号保持阻塞
	- SIG_SETMASK：阻塞set中的信号，原有正在阻塞的信号自动解除 
	- SIG_UNBLOCK：解除set中的信号
#### 信号的捕捉
- 在信号到达之前给信号关联一个指定的响应函数，让其到达之后自动运行该函数
- void (\*signal(int sig,void (\*func)(int)))(int);
- 返回值类型：void(\*)(int);
- 返回值含义：返回一个指向原有的与指定信号关联的函数
- 参数：
	- sig：指定要关联的信号
	- func：指定要关联的响应函数
#### 信号的默认处理
- 如果程序对信号没有做任何预先准备，那么当信号到达时，则会按照信号的默认规则进行响应
- 默认规则有：
	- Term：中断目标进程
	- Core：中断目标进程，且产生核心转储文件core
	- Stop：暂停目标进程，直到收到信号SIGCONT
	- Cont：回复目标进程的运行
	- lgn：忽略信号
- 注意：
	- Term和Core都是中断程序，但是Core处理方式还会产生转储文件core，core文件即程序在被中断的瞬间其内存映像的快照
