#  01.进程与程序
## 基本概念
- **程序**：编译后产生的，格式为ELF的，存储与硬盘的文件
- **进程**：程序中的代码和数据，被加载到内存中运行的过程
- 程序是静态的概念，进程是动态的概念
- 在Linux中程序文件的格式都是ELF，这些文件在被执行的瞬间，就被载入内存，就是将数据段、代码段等运行时必要的资源拷贝到内存，另外系统会分配相应的栈、堆等内存空间给这个进程，使之成为一个动态的实体。
## 进程的组织方式
- 在Linux中除系统的初始进程外，其余所有进程都是通过一个父进程复刻（fork）而来的，因此在整个Linux系统中所有进程都起源于相同的初始进程。
- 最开始的系统进程叫systemd，其身份信息在系统启动前就已经存在于系统分区，在系统启动时直接复制到内存。
## 进程的复刻（fork)
- 除系统的初始进程之外，其它的所有进程都是通过fork()复刻而来的。
- 一个父进程复刻一个子进程时，会将自身所有资源复制一份
	- **一样的有**：
		1. 实际UID和GID，以及有效UID和GID
		2. 所有环境变量
		3. 进程组ID和会话ID
		4. 当前工作路径
		5. 打开的文件
		6. 信号相应函数
		7. 整个内存空间，包括栈、堆、数据段、代码段、标准IO的缓冲区等
	- **不同**：
		1. 进程号PID
		2. 记录锁，子进程不会获得父进程对某一文件加的锁
		3. 挂起的信号
## 进程的状态
- 所有进程都有一个父进程
- 父进程复刻自身得到一个子进程
- 新创建的子进程拥有于父进程一样的执行代码、内存空间等信息，并处于就绪状态
- 当进程退出时，不论是否是主动退出，进入僵尸态，僵尸态下进程无法运行，也无法被调度，但其所占用的系统资源还没有释放。僵尸状态是进程的必经状态，编程过程既不能避免僵尸状态但要避免长时间处于僵尸状态。
- 僵尸态进程要等待其父进程对其进行资源回收后才能变成死亡态，死亡态的进程所占据的系统资源可以随时被系统回收
# 02.进程基本API
## 进程的创建
- pid_t fork();
- **主要功能**：将当前的进程复制一份，然后这两个进程同时从本函数的下一语句开始执行。
- **接口解析**：
	- 所有的代码、变量都会复制成两份
	- 该函数会返回两次，一次返回父进程，值是子进程的PID，一次返回子进程，值固定为0；
	- 父子进程是并发执行的，没有先后次序，若要控制次序要依赖于信号量、互斥锁、条件量等其它条件
## 进程的回收
- pid_t wait(int \*wstatus);
- **主要功能**：
	- 阻塞当前进程
	- 等待其子进程退出并回收其系统资源
- **接口解析**：
	- 如果当前进程没有子进程则该函数立即返回
	- 如果当前进程有不止一个子进程，则该函数会回收第一个变成僵尸态的子进程的系统资源
	- 子进程的退出状态（包括退出值、终止信号等）将被放入wstatu所指示的内存中，若指针为NULL则代表当前进程放弃其子进程的退出状态
	- 可以用一个int类型的status来存放子进程的退出状态，包含了子进程退出的诸多信息:
		 宏                             功能             
		WIFEXITED(status)           判断子进程是否正常退出    
		WEXITSTATUS(status)      获取正常退出的子进程的退出值 
		WIFSIGNALED(status)      判断子进程是否被信号杀死   
		WTERMSIG(status)           获取杀死子进程的信号的值   
- **其它接口**：
	- pid_t waitpid(pid_t pid,int \*wstatus,int options);
	- 可以通过参数pid指定想要回收的子进程
	- 可以通过options来指定非阻塞等待
- **PID取值**：
	- <-1：等待组ID等于pid绝对值的进程组中的任意一个子进程
	- -1：等待任意一个子进程
	- 0：等待本进程所在的进程组中的任意一个子进程
	- >0：等待指定pid的子进程
- **options取值**：
	- 0：阻塞等待子进程的退出
	- WNOHANG：若没有僵尸进程则函数立即返回
	- WUNTRACED：当子进程暂停时函数返回
	- WCONTINUED：当子进程收到信号SIGCONT继续运行时函数返回
