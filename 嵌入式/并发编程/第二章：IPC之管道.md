# 01.匿名管道
## 进程间通信概览
- **管道**：
	- 匿名管道pipe：适用于亲缘关系进程间的、一对一的通信
	- 具名管道fifo：适用于任何进程间的一对一、多对一的通信
- **套接字socket**：适用于跨网络的进程间通信
- **信号**：异步通信方式
- **system-V IPC对象**：
	- 共享内存：最高效的通信方式
	- 消息队列：带标签增强版的管道
	- 信号量组：也称为信号灯，用来协调进程间或线程间的执行进度
- **POSIX信号量**：
	- 匿名：适用于多线程
	- 具名：适用于多进程
## 匿名管道PIPE
### 基本逻辑
- 不管哪种管道，在Linux下都属于文件的范畴，区别是匿名管道没有名称，因此无法通过open创建或打开，但是其有自己的创建接口，其读写方式和普通的文件一样支持read/write操作
- 所谓管道指的是这些文件不能进行定位
### 函数接口：
- int pipe(int fd[2]);
- 匿名管道拥有两个文件描述符，一个专用于读的fd[0]，一个专用于写的fd[1]，因此上述接口需要传递一个至少包含两个整形元素的数组过去，用来存放这两个特定的描述符
- 匿名管道描述符只能通过继承的方式传递给后代进程，因此只能用于亲缘进程间的通信，由于没有文件名其它非亲缘进程无法获取匿名管道的文件描述符
- 不能有多个进程同时对匿名管道进行写操作，否则数据可能被覆盖
- 一般而言，不需要用到的文件描述符都最好及时关闭，避免不必要的副作用或浪费系统资源
### 管道的读写特性
- **术语约定**：
	- 读者：对管道有读权限的进程
	- 写者：对管道有写权限的进程
- **读写特性**：
	- 有写者时，如果管道中有数据则正常读取，若管道中没有数据则阻塞等待
	- 无写者时，如果管道中有数据就正常读取，若管道中没有数据则直接返回
	- 有读者时，如果缓冲区未满就正常写入，若缓冲区已满就阻塞等待
	- 无读者时，不管是否缓冲已满，立刻收到SIGPIPE
### 管道的阻塞特性
- 当试图读取一个空的管道或者写入一个缓冲区已满的管道时，读写操作就会默认进入阻塞状态。
- 阻塞装态实际就是系统将该进程挂起，等待资源就绪再继续调度的一种状态，这种阻塞有利于高效利用闲置的CPU资源提高 系统的吞吐量
- 普通文件默认是非阻塞的且不可修改
- 管道文件默认是阻塞的，可修改
- 管道打开时必须有读者和写者否则open也会阻塞
# 02.具名管道
## 具名管道概述
- 相对于匿名管道来说具名管道更接近普通文件，有文件名、可以open打开、支持read/write等读写操作
- **具名管道特性**：
	- 不支持定位操作
	- 和PIPE一样的管道读写特性
	- 使用专门的接口创建：mkfifo()；
	- 再文件系统中有对应节点，支持使用open()打开管道
	- 支持多路同时写入
## 函数接口
- int mkfifo(const char \*pathname,mode_t mode);
- pathname即具名管道的名称，若是新建的管道文件，则需保证创建路径位于Linux系统房内，不可以将管道文件创建再共享文件夹中
- mode是文件权限模式，权限为八进制
- 具名管道一旦没有任何读者和写着，系统判定管道处于空闲状态，会释放管道中的所有数据
